# PulseAudio on Phase 14

Status, 2026-10-26: both images use PipeWire, WirePlumber, and `pipewire-pulse`. ALSA is the hardware backend, and PipeWire's BlueZ monitor owns A2DP. There is no PulseAudio daemon and BlueALSA is not started. The current contract is `docs/ARCHITECTURE.md`.

There is no `wpctl` or `pw-metadata` snapshot of that unplug, and no evidence that PipeWire exited. Linux 7.2 `drivers/gpu/drm/drm_sysfs.c` emits `HOTPLUG=1` on the primary card from both `drm_sysfs_hotplug_event` and `drm_sysfs_connector_hotplug_event`. DesignWare HDMI calls `drm_helper_hpd_irq_event`, which uses the single-connector variant. The image's udev rule matched `card*-HDMI-A-*`, so `zlyme-audio hdmi-event` did not run and the earlier connector-status check never saw the unplug. The rule now matches a `change` with `HOTPLUG=1` on a `drm_minor` named `card0` or `card1`. eudev 3.2.14 waits for that program and kills that pid on timeout. The ELD recheck is started with `start-stop-daemon -b`, which `setsid`s and double-forks before the handler returns. `zlyme-my355-20261022-0b35a90e9388.tar` (source `0b35a90e9388bb2aea04a4744118323a48b68f6a`) contains that rule. On 2026-10-23 the maintainer installed it and accepts HDMI television audio, disconnect back to the speaker, the external-audio mark clearing, reconnect back to the television, and Bluetooth disconnect and reconnect. Volume and mute, including sound returning after mute, are accepted on that image. The `74597688` failure above stays the record of that image. Stream migration was accepted by ear on `0b35a90`: the same playback returned to the speaker and later to the television. It was not captured with `wpctl`.

## Superseded PulseAudio candidate

The following paragraphs were removed from the current architecture on 2026-10-26. They describe the retired PulseAudio and BlueALSA candidate, not the running graph.

For the Miyoo Flip:

- the local codec is the RK817, identified by stable ALSA card ID `rk817ext`. HDMI is a separate card. Roles are `codec`, `hdmi`, and `bt`. Historical PulseAudio candidate: Pulse sink names were those same three words;
- `rcS` does not start PipeWire. `rc.late` starts it after D-Bus, in parallel with InputPlumber. The status file is `/run/zlyme/pipewire/service`. `ready` requires a codec Audio/Sink. The historical PulseAudio boot below is not the current product path. `rcS` used to start `S21pulse` in Class A after `S20alsa` and before `S25jackd`. `rc.late` does not start it. `S21pulse` starts one PulseAudio 17 process as the `pulse` user and returns when that process is launched, before NextUI. It passes `-n`, so `system.pa` is not loaded. It does not pass `--system`. PulseAudio 17 system mode creates `/var/lib/pulse` before it drops privileges, and `/var/lib` is on the read-only squashfs, so that process exits before it opens a socket. `start-stop-daemon -c pulse:pulse` puts the process in `audio` and `pulse-access`, which is what lets it open the RK817 device and talk to BlueALSA. Runtime, state, and the cookie stay under `/run/zlyme/pulse`. The script returns when the process has been launched. A background check, bounded to thirty seconds, records `alive`, then `socket`, then `ready` only when the `codec` sink is listed. If that sink is missing while the server is up, the check loads `module-alsa-sink` again with the same arguments. It also sets group `audio` on existing `/dev/snd` nodes. ALSA's card lookup opens those nodes and, when the open fails, reports `Cannot get card index` rather than a permission error. The kernel short name `rk817_ext` is not the ALSA id. `hw:rk817ext,0` is. The daemon log level is info so that open error is kept. A dead process records `failed:` plus the daemon's own error from `/run/zlyme/pulse/daemon.log`. A live process whose codec sink is missing after that retry is not `ready`. That check does not delay the frontend. `launching` is not `ready`. `S50pulseaudio` from Buildroot exits immediately so a second server is not started. Module loading stays allowed because the HDMI and Bluetooth sinks are loaded later. There is no TCP listener. The socket directory `/run/zlyme/pulse` is mode 0700 and owned by `pulse`. Anonymous authentication is off. Clients in `pulse-access`, or a root client presenting the cookie in that directory, may connect;
- Historical PulseAudio candidate: the codec sink is `hw:rk817ext,0`. Codec and HDMI use 12 fragments of 1024 bytes, about 64 ms at 48 kHz. The Bluetooth sink stays at 4 fragments. Remixing stays at PulseAudio's default, which is on. A mono client such as PICO-8 is copied onto both front channels. `enable-remixing=no` leaves that mono stream silent on a stereo sink, and PulseAudio 17 deprecates that setting. The HDMI sink is loaded only when the HDMI ELD reports an audio SAD, not because the cable is connected. The Bluetooth sink is `module-alsa-sink` on a BlueALSA A2DP PCM. Pulse's BlueZ module is not loaded. BlueALSA remains the A2DP owner. A HID pad does not create a sink;
- Historical PulseAudio candidate: `zlyme-audio` stored the selected sink and the volume in `/storage/.config/audio.conf`, set the PulseAudio default sink, moves streams that are already playing, and sets the same volume on every sink. Flat volumes are off, so the setting stays in 0–100 percent. The codec sink opens `hw:rk817ext,0`, so the old `FlipVolume` softvol is not in that path. The first time the codec sink is usable, the saved `FlipVolume` percentage is copied into the Pulse volume and `ZLYME_VOLUME_SRC=flipvolume` is written in the same replacement of the state file. Later boots leave that file alone. A missing saved mixer level starts at 40 percent. Mute and the saved pre-mute value stay;
- speaker/headphone switching is still the RK817 `Playback Mux` control. `zlyme-jackd` follows the headphone-jack evdev switch and sets it. Pulse keeps the codec device open. The mux change does not restart a game;
- Historical PulseAudio candidate: `zlyme-btsink` picked the sink: an A2DP headset first, then HDMI when its ELD reports audio, then the codec. A HID pad does not count. The choice is recorded only after the server is up, the sink module is the one for the current device, and the default sink has moved. A down server, a failed load, a disappeared sink, a new headset address, or a later HDMI audio descriptor is tried again. A stored module number is not treated as proof of the current headset. A change moves Pulse streams and does not kill NextUI or the emulator.

Earlier images used `dmix` and one `FlipVolume` softvol, and `zlyme-btsink` killed the player so it would reopen the PCM. That graph is not the default anymore. `FlipVolume` is read once, the first time the codec sink is usable, and copied into the Pulse volume. That copy has not been checked on a Flip. The named `flipsink_*` devices are still in `asound.conf` so a program that opens one by name still has a path. Opening one while Pulse holds `hw:rk817ext,0` contends for that PCM. The default PCM does not open them. A program that opens `hw:` still bypasses the server. Volume buttons call `zlyme-audio setSystemVolume`. On `d1e6368` the ALSA id in `/proc/asound/card1/id` is `rk817ext`. `hw:rk817ext,0` opens. `hw:rk817_ext,0` does not. The boot retry stopped after six failed lookups of the real id. A later load of that same id created the codec sink and accepted a short stream at 8 percent with the playback mux on speakers. A person has not confirmed the speaker.


The paragraphs below record the earlier candidate. Present-tense statements there, including a PulseAudio server, BlueALSA owning A2DP, and `zlyme-btsink` choosing the sink, describe that candidate. They are not the running system.

Phase 13 (`8b4218aa`, published as `zlyme44.3`) played through ALSA. `asound.conf` made `default` a `dmix` plus one `FlipVolume` softvol. BlueALSA was the Bluetooth playback device. Programs that opened `default` shared the RK817 PCM.

Phase 14's earlier candidate played through one PulseAudio 17 server. The current graph does not. The server opens `hw:rk817ext,0`. `default` is the Pulse ALSA plugin, so an ordinary ALSA client, including SDL with `SDL_AUDIODRIVER=alsa` and PICO-8, reaches that server. Native `libpulse` clients use the same socket. `flipsink_*` remains for a program that opens that name. Nothing in the shipped launchers does. The Music Player sets `SDL_AUDIODRIVER=alsa`, which follows `default`.

`/proc/asound/card1/id` is `rk817ext`. The kernel short name `rk817_ext` is the headphone input name (`rk817_ext Headphones`) and is not an ALSA card id.

`enable-remixing` defaults to yes. PulseAudio 17 `daemon.conf` says setting it to no has no known valid use case and is deprecated. `enable-remixing=no` sets `disable_remixing`, and `resampler.c` then copies a channel only when the position names match. A mono stream is `mono`. A stereo sink is `front-left` and `front-right`. Nothing matches, so both speakers stay at zero. PICO-8 Splore opens that mono stream through the ALSA plugin. The override is not set.

BlueALSA remains the A2DP owner. Its own integration note says the Pulse `module-alsa-sink` bridge is experimental and that a Pulse server should use `module-bluez5-discover` instead: [PulseAudio integration](https://github.com/Arkq/bluez-alsa/wiki/PulseAudio-integration). Pulse's Bluetooth page is [Software/PulseAudio/Documentation/User/Bluetooth](https://www.freedesktop.org/wiki/Software/PulseAudio/Documentation/User/Bluetooth/). The image contains `module-bluez5-discover.so`. It is not loaded. Loading it while BlueALSA owns the A2DP profile would register two owners. That switch needs a hardware session that can stop one owner, try the other, and put BlueALSA back. It has not been run. BlueALSA stays.

`zlyme-btsink` creates the next sink and moves the default before it unloads the previous optional sink. A failed headset load leaves HDMI in place.

The codec retry stays in the background for thirty seconds. `udev` on `f48b5bf` started about a second before Pulse, and the five-second window expired while `hw:rk817ext,0` still could not be opened. The retry was not removed. Routine Pulse logs are notice. `ZLYME_PULSE_LOG=info` is the one-boot diagnostic.

PPSSPP underruns were reported with sound still audible. The codec fragment size was not changed. There is no new measurement of those underruns on this pass.
